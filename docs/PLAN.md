## 0. Старт (выполнить один раз)

1. Проверить, что `gh` авторизован: `gh auth status`. Если нет — попросить владельца выполнить `gh auth login`.
2. Создать **закрытый** репозиторий с кодом:
   ```bash
   gh repo create ratatosk --private --description "P2P voice & screen sharing for friends" --clone
   cd ratatosk
   ```
3. Создать **публичный** репозиторий только для релизов (без кода, см. раздел 8):
   ```bash
   gh repo create ratatosk-releases --public --description "Ratatosk installers" --add-readme
   ```
4. Положить в код-репозиторий: этот файл как `docs/PLAN.md`, иконки из `assets/icon/` в `build/icons/` (их же использует electron-builder).
5. Создать метки:
   ```bash
   for l in "mvp:0E8A16" "v1:1D76DB" "later:BFD4F2" "area:infra:5319E7" "area:network:D93F0B" \
            "area:audio:FBCA04" "area:screen:0052CC" "area:ui:C5DEF5" "area:release:6F42C1" \
            "area:perf:B60205" "idea:EDEDED"; do
     gh label create "${l%:*}" --color "${l##*:}" --force
   done
   ```
   (`${l%:*}` — имя метки вместе с двоеточием внутри, `${l##*:}` — цвет.)
6. Создать milestones: `M0 Фундамент`, `M1 Комната и подключение`, `M2 Голос`, `M3 Демонстрация экрана`, `M4 Надёжность и производительность`, `M5 Релиз 0.1`, `v1`, `Backlog`.
   ```bash
   gh api repos/{owner}/ratatosk/milestones -f title="M0 Фундамент"
   # ... и так далее для каждого
   ```
7. Создать issues из раздела 10 — по одному на пункт, с заголовком, телом (описание + критерии приёмки как чеклист `- [ ]`), метками и milestone. Номера issues в разделе 10 — порядковые; реальные номера GitHub могут отличаться, ссылки на зависимости в телах issues поправить на реальные.
8. Создать Project (доска) не обязательно; достаточно milestones.
9. Сообщить владельцу: ссылки на оба репозитория, число созданных issues, что следующим берётся issue #1.

## 1. Что строим

**Ratatosk** — десктопное приложение для голосовых созвонов и демонстрации экрана с друзьями, без собственного сервера.

- Платформы: **Windows, macOS, Linux**. Мобильных клиентов нет.
- До **15 человек** в комнате.
- Приоритет — **производительность и простота**, а не количество функций.
- Своего VPS нет. Тот, кто создаёт комнату, становится **хостом**: его приложение поднимает встроенный сервер (сигнализация + ретранслятор медиа). Остальные подключаются к нему напрямую по ссылке-приглашению.
- Название — от белки Рататоск из скандинавской мифологии, которая носила сообщения по мировому древу.

## 2. Архитектура

```
              Хост (Electron)
  ┌──────────────────────────────────────┐
  │ Renderer: UI + mediasoup-client      │
  │ Main: окно, deep links, хранилище    │
  │ Utility process «host»:              │
  │   • HTTPS + WSS (сигнализация)       │◄── участник 1..14 (WSS, TCP 47000)
  │   • mediasoup Worker + Router        │◄── медиа (UDP 47000, запасной TCP)
  │   • WebRtcServer: один порт на всех  │
  │   • UPnP / NAT-PMP / PCP             │
  └──────────────────────────────────────┘
```

- **Топология: только SFU на хосте.** Каждый участник отправляет хосту по одному потоку, хост пересылает без перекодирования. Mesh не реализуем.
- **Один порт.** `mediasoup.WebRtcServer` позволяет всем транспортам использовать один UDP-порт (и TCP-порт как запасной). Сигнализация WSS — на TCP того же номера. Пробрасывается только `47000/UDP` и `47000/TCP` (номер настраивается).
- **Комната живёт, пока у хоста открыто приложение.** Хост вышел — комната закрыта, всем показывается понятное сообщение.
- **Безопасность:**
  - сигнализация только по WSS с self-signed сертификатом; SHA-256 отпечаток сертификата лежит в ссылке, клиент его пиннит;
  - пароль проверяется challenge-response (HMAC-SHA256), по сети не передаётся; ограничение попыток;
  - медиа зашифровано DTLS-SRTP всегда;
  - Electron: `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, строгий CSP, никакого удалённого контента.

### Экономия трафика хоста (обязательно)

- **Голос:** пересылать каждому только **3 самых громких** голоса (ActiveSpeakerObserver / AudioLevelObserver + pause/resume consumers). Opus с DTX.
- **Экран:** 2 потока (≈1080p и ≈360p). Хост выбирает поток для каждого зрителя по его окну и сети; свёрнутым окнам — пауза. Не simulcast: Chromium кодирует simulcast H.264 только программно, а одиночный поток ≈1080p — аппаратно; ≈360p — дешёвый программный VP8 (решение #34, замер в `docs/perf/README.md`).
- Ориентир: экран 1080p на 14 зрителей ≈ 40 Мбит/с отдачи у хоста, голос ≈ 2 Мбит/с.

## 3. Стек

| Слой | Выбор |
|---|---|
| Оболочка | Electron (актуальная стабильная) |
| Язык | TypeScript (strict) |
| UI | SolidJS + Vite (electron-vite) |
| Пакетный менеджер | pnpm |
| SFU на хосте | mediasoup (worker — отдельный бинарник, класть в `asarUnpack`) |
| Медиа в клиенте | mediasoup-client поверх Chromium WebRTC |
| Сигнализация | `ws` поверх `https`, JSON-сообщения (zod для валидации) |
| Сертификат | генерация self-signed (node-forge или `selfsigned`), хранится в userData, один на установку |
| Проброс порта | библиотека UPnP + NAT-PMP/PCP (например `@achingbrain/nat-port-mapper`; выбрать актуальную и поддерживаемую) |
| Push-to-talk (v1) | `uiohook-napi` |
| Хранилище | JSON в userData (`electron-store`) |
| Тесты | vitest (юнит), Playwright for Electron (e2e), нагрузочный тест — см. issue #33 |
| Сборка | electron-builder |
| CI | GitHub Actions |
| Шрифты | Onest, JetBrains Mono (OFL 1.1) — пакеты `@fontsource-variable/onest` и `@fontsource-variable/jetbrains-mono`, **локально в бандле**, не с Google Fonts |
| Иконки | Lucide (`lucide-solid`, ISC), обводка 2 px; других наборов не смешивать |

Ассеты — **только открытые** (OFL / MIT / ISC / Apache-2.0). Лицензии шрифтов и иконок кладутся в `build/licenses/` и показываются в «О программе».

## 4. Структура репозитория

```
ratatosk/
  apps/desktop/
    src/main/          # главный процесс: окна, deep links, IPC, хранилище
    src/host/          # utility process: https+wss, mediasoup, nat
    src/preload/       # contextBridge API
    src/renderer/      # Solid UI, mediasoup-client
    src/shared/        # типы протокола, zod-схемы, формат ссылки
  build/icons/         # иконки (из assets/icon)
  docs/PLAN.md         # этот файл
  docs/design/         # макеты экранов (html + pdf)
  docs/INSTALL.md      # инструкция для друзей (RU)
  .github/workflows/   # ci.yml, release.yml
```

Монорепо не обязательно — допустим один пакет, если так проще. Главное — граница main / host / preload / renderer / shared.

## 5. Протокол

### Ссылка-приглашение

```
ratatosk://join?v=1&h=<host>&p=<port>&r=<roomId>&fp=<sha256 base64url>[&k=<password>]
```

- `h` — IPv4, IPv6 (в квадратных скобках) или DNS-имя.
- `k` — пароль, только если хост поставил галочку «вшить пароль в ссылку».
- Парсер строгий, неизвестная версия `v` → понятная ошибка «Обнови приложение».

### Сообщения сигнализации (черновик)

`hello` → `challenge {nonce, room: {name, peerCount, hasPassword}}` → `auth {name, hmac}` → `welcome {peers, routerRtpCapabilities}` | `error {code}`

До авторизации хост раскрывает только название комнаты, **число** участников и нужен ли пароль — имена участников не раскрываются (решение владельца). Этого же ответа хватает для статуса недавних комнат на главном экране.
Далее: `createTransport`, `connectTransport`, `produce`, `consume`, `resumeConsumer`, `setScreenLayer`, `pauseProducer`, `peerJoined`, `peerLeft`, `activeSpeakers`, `screenShareStarted/Stopped`, `roomClosed`, `ping/pong`.
Коды ошибок: `WRONG_PASSWORD`, `ROOM_FULL` (15), `TOO_MANY_ATTEMPTS`, `VERSION_MISMATCH`, `SCREEN_BUSY`.

## 6. Бюджеты производительности (проверяются в M4)

- Задержка голоса end-to-end ≤ 150 мс в пределах одной страны.
- Клиент в голосовом звонке: CPU ≤ 5 %, RAM ≤ 250 МБ.
- Хост с 15 участниками и одной демонстрацией: CPU процесса host ≤ 10 % на современном 4-ядерном ПК.
- Без звонка приложение в фоне не потребляет CPU.
- Холодный старт ≤ 2 с.
- Демонстрация экрана — аппаратный кодировщик (H.264), VP8 только как запасной.

## 7. Экраны (по макетам)

Макеты экранов 1–5: `docs/design/ratatosk-screens.html` (открыть в браузере) и `docs/design/ratatosk-screens.pdf`. Где макет расходится с планом, действует план:
- ссылка-приглашение — формат из раздела 5 (`v`, отдельный `p`), а не `h=host:port` с макета;
- до входа показывается только число участников («Внутри 2 человека»), не имена;
- тип соединения пишется «через организатора» (например, «24 мс · через организатора»), а не «напрямую» / «P2P» — медиа идёт через SFU организатора;
- тексты интерфейса нейтральные (#88): «организатор» вместо «хост», без «друзей», безличные формулировки вместо обращения на «ты»/«вы», без приветствий и разговорных вопросов (тест `src/main/neutral-copy.test.ts`);
- битрейт голоса — по issue #25 (32–48 кбит/с), а не 64 кбит/с с макета;
- ползунок громкости 0–200 %: 100 % — посередине шкалы.

Тёмная тема: фон `#111315`, поверхности `#1A1D21`, рамки `#2A2E35`, текст `#ECEEF0`, вторичный текст `#9AA3AD`, акцент мятный `#7FD1AE` (текст на нём `#0E1F18`), опасное действие `#D9363E`. Шрифт Onest, моноширинный JetBrains Mono. Радиусы 12–20 px, кнопки высотой ≥ 44 px.

1. **Главный:** шапка (логотип, «Ratatosk», настройки, имя); две карточки — «Создать комнату» и «Войти по ссылке» (поле для ссылки); список недавних комнат (статус: идёт / не запущена / хост не в сети); строка состояния сети внизу.
2. **Создание комнаты:** название, пароль + «Сгенерировать», галочка «вшить пароль в ссылку», режим экрана (Авто / Чёткий текст / Плавно), «Дополнительно» (порт). Справа — проверка сети (порт, внешний адрес, IPv6, отдача), ссылка + «Скопировать», кнопка «Открыть комнату».
3. **Вход по ссылке:** название комнаты, кто внутри, отметка «сертификат совпадает», имя, пароль, выбор микрофона + индикатор уровня, «войти с выключенным микрофоном».
4. **Звонок:** шапка (название, таймер, пинг, «Пригласить»); плитки участников (рамка у говорящего, значок выключенного микрофона, метка «организатор»); громкость каждого 0–200 % — в меню «⋯» на плитке (#77); нижняя панель — Микрофон, Звук, Экран, Настройки, Выйти; подсказка хоткеев.
5. **Демонстрация экрана:** большая область, плашка «Экран <имя>», «1080p · 30 к/с · битрейт», «на весь экран»; полоса участников; та же нижняя панель.
6. **Дорисовать в коде** (макетов нет, стиль тот же): «Нельзя хостить», «Неверный пароль», «Переподключение…», «Хост закрыл комнату», «Настройки звука», выбор источника для демонстрации.

## 8. Как раздавать сборки друзьям

### Схема

- Код — в **закрытом** `ratatosk`.
- Установщики — в **публичном** `ratatosk-releases` (только релизы, без исходников). Друзьям не нужен аккаунт GitHub, ссылку можно просто отправить. Приложение без ссылки-приглашения бесполезно, так что публичность установщиков не раскрывает ничего важного.
- Если **[решает владелец]** установщики тоже должны быть закрыты — альтернатива: приватное хранилище (например, Cloudflare R2) с неугадываемыми ссылками. По умолчанию — публичный releases-репозиторий.

### Пайплайн (`.github/workflows/release.yml`)

- Запуск по тегу `v*.*.*` в закрытом репозитории.
- Матрица: `windows-latest` (x64, NSIS `.exe`), `macos-latest` (arm64 `.dmg`), актуальный Intel-образ macOS (x64 `.dmg`; `macos-13` выведен из эксплуатации — проверить, например `macos-15-intel`), `ubuntu-latest` (x64 `.AppImage` + `.deb`). Mac собирать отдельно под arm64 и x64, без universal — так проще с бинарником mediasoup.
- Каждая сборка на своей ОС (нативные бинарники mediasoup и uiohook).
- Публикация в `ratatosk-releases` через fine-grained токен с правом `contents:write` только на этот репозиторий; хранить в секрете `RELEASES_TOKEN`.
- Прикладывать `SHA256SUMS.txt` и короткие release notes на русском.
- Помнить про лимиты GitHub Actions для приватных репозиториев: macOS-минуты считаются с повышенным множителем. Собирать только по тегу, не на каждый коммит.

### Подпись и предупреждения ОС

- **Windows:** без сертификата подписи SmartScreen покажет «Windows защитила ваш компьютер» → «Подробнее» → «Выполнить в любом случае». Только при первом запуске.
- **macOS:** без Apple Developer ID ($99/год) — только ad-hoc подпись (нужна для Apple Silicon). Gatekeeper заблокирует первый запуск; в новых macOS разрешение даётся в «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть». Также нужно разрешение «Запись экрана» и «Микрофон». **[решает владелец]** покупать ли Developer ID — с ним пропадают предупреждения и работает автообновление на mac.
- **Linux:** AppImage (`chmod +x`, запуск) или `.deb`. Для deep links AppImage нужно один раз интегрировать (`.desktop`-файл) — приложение делает это само при первом запуске.

### Обновления

- **MVP:** при запуске приложение проверяет последний релиз через GitHub API публичного репозитория и показывает плашку «Доступна версия X — скачать» со ссылкой. Работает на всех ОС.
- **v1:** `electron-updater` (провайдер github → `ratatosk-releases`) для автообновления на Windows и Linux (AppImage). На macOS автообновление требует подписанного приложения — до покупки Developer ID остаётся плашка.
- Совместимость: хост и клиент обмениваются версией протокола; при несовпадении — понятная ошибка «Обнови приложение».

### Для друзей

`docs/INSTALL.md` (на русском) — копируется в README `ratatosk-releases`: где скачать, как пройти предупреждения на каждой ОС, какие разрешения дать, что делать, если «нельзя хостить».

## 9. Правила работы агента

1. Идти по milestones по порядку: M0 → M1 → … → M5, затем v1. Внутри milestone — по номерам, с учётом зависимостей.
2. Один issue — одна ветка `issue-<номер>-<slug>` — один PR с `Closes #<номер>`. Коммиты в стиле Conventional Commits со ссылкой на issue.
3. Перед PR: `pnpm lint`, `pnpm typecheck`, `pnpm test` зелёные. Для UI — скриншот в описании PR.
4. Критерии приёмки из issue отмечать галочками в PR. Если критерий нельзя выполнить — написать почему в issue, не закрывать молча.
5. Не расширять scope. Новые идеи — отдельный issue с меткой `idea`, без milestone.
6. Не коммитить секреты, токены, сертификаты.
7. Спрашивать владельца перед: платными сервисами, покупкой сертификатов подписи, сменой стека, публикацией кода, изменением формата ссылки после релиза 0.1.
8. После каждого закрытого milestone — короткий отчёт владельцу: что готово, что отложено, как проверить руками.
9. Ручную проверку голоса и экрана на нескольких машинах агент сделать не может — в конце M2, M3 и M5 подготовить чеклист и попросить владельца проверить с друзьями.

Открыть TCP и UDP порт при создании комнаты, закрыть при выходе. Ручной порт в «Дополнительно».
- при успехе возвращается внешний адрес
- мэппинг удаляется при закрытии комнаты и при выходе из приложения
- при неудаче — понятный статус, а не исключение

**#9 Проверка возможности хостить** · `mvp` `area:network` · M1
Эвристика: проброс удался + внешний IPv4 публичный (не RFC1918, не 100.64.0.0/10 — признак CGNAT) или есть глобальный IPv6.
- итог «можно / нельзя» + причина простыми словами
- строка состояния на главном экране показывает результат

**#10 Оценка отдачи хоста** · `mvp` `area:network` `area:perf` · M1
До звонка — опциональный замер через публичный speed-test (например, speed.cloudflare.com; отключаемо в настройках). Во время звонка — оценка по статистике WebRTC/mediasoup.
- на экране создания комнаты: «Отдача N Мбит/с — хватит на K человек / на экран в 1080p или 720p»
- если замер выключен или не удался — строка скрыта, ничего не ломается

**#11 Формат ссылки-приглашения** · `mvp` `area:network` · M1
`src/shared/invite.ts`: сборка и строгий разбор (раздел 5), юнит-тесты, включая IPv6 и битые ссылки.
- 100 % покрытие тестами модуля

**#12 Deep links ratatosk://** · `mvp` `area:infra` · M1
Регистрация протокола на трёх ОС, single-instance lock, передача ссылки в уже запущенное приложение; интеграция `.desktop` для AppImage.
- клик по ссылке открывает экран «Вход по ссылке» с заполненными данными

**#13 Аутентификация по паролю** · `mvp` `area:network` · M1
Challenge-response HMAC-SHA256, пароль не передаётся. Не более 5 неудачных попыток с одного адреса за минуту. Пустой пароль = вход без пароля.
- `WRONG_PASSWORD`, `TOO_MANY_ATTEMPTS` обрабатываются в UI

**#14 Пиннинг сертификата хоста** · `mvp` `area:network` · M1
Клиент сверяет отпечаток сертификата с `fp` из ссылки; несовпадение — отказ подключения и предупреждение.
- тест: подмена сертификата → подключение невозможно

**#15 Главный экран + недавние комнаты** · `mvp` `area:ui` · M1
По макету 1. Недавние комнаты в electron-store; статус хоста — попытка лёгкого подключения при открытии экрана (`hello` → `challenge.room`, без авторизации).
- статус показывает только число участников
- сохранённый пароль шифруется через Electron `safeStorage`, в открытом виде не хранится

**#16 Экран «Создание комнаты»** · `mvp` `area:ui` · M1
По макету 2: форма, генератор пароля (слова через дефис), проверка сети, ссылка, копирование, «Открыть комнату».

**#17 Экран «Вход по ссылке» + проверка микрофона** · `mvp` `area:ui` `area:audio` · M1
По макету 3: имя, пароль, выбор микрофона, индикатор уровня, вход с выключенным микрофоном.
- до входа видно только название комнаты и число участников, имена — нет

**#18 Экраны ошибок** · `mvp` `area:ui` · M1
«Нельзя хостить» (с советами: проброс вручную / IPv6 / пусть хостит другой / Tailscale), «Хост не в сети», «Неверный пароль», «Хост закрыл комнату», «Комната заполнена», «Обнови приложение».

### M2 Голос

**#21 Активные говорящие (top-3) и индикатор** · `mvp` `area:audio` `area:perf` · M2

**#22 Микрофон и звук: выкл/вкл + хоткеи в фокусе** · `mvp` `area:audio` `area:ui` · M2

**#23 Громкость каждого участника** · `mvp` `area:audio` · M2

**#24 Устройства и экран настроек звука** · `mvp` `area:audio` `area:ui` · M2

**#25 Параметры Opus и обработка звука** · `mvp` `area:audio` `area:perf` · M2

### M3 Демонстрация экрана

**#26 Выбор источника** · `mvp` `area:screen` · M3

**#27 Публикация экрана: simulcast + аппаратный кодек** · `mvp` `area:screen` `area:perf` · M3

**#29 Один показывающий** · `mvp` `area:screen` · M3
