# Ручная проверка перед релизом

Сценарии для живой проверки на трёх ОС: всё, что автотесты не видят — установщики, предупреждения систем, настоящие микрофоны и экраны, разные сети. Проходится перед каждым релизом на собранных установщиках (#38). Как установить и пройти предупреждения — [INSTALL.md](INSTALL.md); роутер, проброс порта и VPN подробно — в #67.

## Что понадобится

- Три компьютера: **Windows 10/11**, **macOS** (лучше и Apple Silicon, и Intel, если есть) и **Linux** (Ubuntu или похожий; если можно — сессия Wayland и X11).
- Хотя бы один участник **в другой сети**: проще всего раздать интернет с телефона. Иначе проверка ничего не скажет о подключении из интернета.
- Организатор — компьютер, у которого внизу главного экрана «Этот компьютер может быть организатором».
- Наушники у всех (без них слышно эхо собственного голоса из чужих динамиков — это не ошибка приложения).
- Около часа на всех.

## Как записывать

Результаты — комментарием в issue релиза, по шаблону:

```
Версия:            0.1.0
ОС:                macOS 15.3, Apple Silicon
Роль:              организатор / участник
Сеть:              домашний Wi-Fi, белый IP / мобильный интернет / …
Не прошло:         номера пунктов + что видно (текст, скриншот)
Заметки:           что показалось странным, медленным, непонятным
```

Проверять на каждой ОС, если у пункта не сказано иное. Пункт «не прошёл» — с текстом на экране или скриншотом: по ним понятно, где искать.

## 1. Установка и первый запуск

1. Скачать установщик для своей ОС со страницы релиза, сверить SHA-256 с `SHA256SUMS.txt`.
2. Установить и запустить, пройти предупреждение системы по [INSTALL.md](INSTALL.md).

- [ ] 1.1 Предупреждение системы — ровно такое, как в INSTALL.md, и проходится описанным способом
- [ ] 1.2 Окно появляется быстро (до 2 с с момента запуска), без белого экрана
- [ ] 1.3 Значок Tolki — в Dock / панели задач / меню приложений, название «Tolki»
- [ ] 1.4 Главный экран: «Создать комнату», «Войти по ссылке», «Недавние комнаты», внизу строка «Этот компьютер может / не может быть организатором…»
- [ ] 1.5 Если «не может» — причина и совет понятны и совпадают с таблицей в INSTALL.md
- [ ] 1.6 Повторный запуск при открытом приложении не открывает второе окно, а показывает первое

## 2. Ссылки `tolki://`

Ссылку отправить себе в мессенджер (Telegram, почта) и кликнуть.

- [ ] 2.1 Приложение закрыто: клик открывает Tolki сразу на экране «Вход по ссылке»
- [ ] 2.2 Приложение открыто: клик выводит его окно вперёд с экраном входа
- [ ] 2.3 Linux AppImage: после первого запуска ссылки открываются кликом (без ручных настроек)
- [ ] 2.4 Ссылка, вставленная в поле «Ссылка-приглашение» на главном экране, + «Войти» — то же самое
- [ ] 2.5 Испорченная ссылка (удалить кусок) — понятное сообщение, а не пустой экран

## 3. Комната (организатор)

На компьютере организатора.

1. «Создать комнату», дождаться «Проверки сети».
2. Ввести название и имя, «Сгенерировать» пароль, режим экрана — «Плавно».
3. «Скопировать ссылку», отправить участникам.
4. «Открыть комнату».

- [ ] 3.1 «Проверка сети»: порт открыт (или понятная причина, почему нет), строка замера «Отдача N Мбит/с — хватит на …» правдоподобна (сравнить со speedtest.net)
- [ ] 3.2 Сгенерированный пароль — три части через дефис, ссылка копируется («Ссылка скопирована»)
- [ ] 3.3 Windows: при первом открытии комнаты появляется запрос брандмауэра; после «Разрешить» участники подключаются
- [ ] 3.4 После «Открыть комнату» организатор попадает в звонок и может говорить; «Пригласить» в шапке копирует ссылку
- [ ] 3.5 «Выйти» у организатора закрывает комнату: у участников «Организатор закрыл комнату»
- [ ] 3.6 Выход из приложения с открытой комнатой: проброс порта убран (в таблице UPnP роутера нет записи Tolki)

## 4. Вход по ссылке (участник)

- [ ] 4.1 До входа видно название комнаты, сколько в ней человек и что пароль нужен; имён участников нет
- [ ] 4.2 Система спрашивает доступ к микрофону (только в первый раз); после разрешения полоска уровня двигается, когда говоришь
- [ ] 4.3 Неверный пароль — «Неверный пароль»; верный — вход в комнату
- [ ] 4.4 «Войти с выключенным микрофоном» — в комнате микрофон выключен, его можно включить
- [ ] 4.5 Доступ к микрофону запрещён в системе — понятное сообщение, можно войти только слушать
- [ ] 4.6 Комната появилась в «Недавних»; при следующем запуске видно, открыта ли она и сколько в ней человек; вход из «Недавних» — без повторного ввода пароля

## 5. Голос

Лучше всего втроём и больше, хотя бы один — из другой сети.

- [ ] 5.1 Все слышат всех; голос чистый, без треска и обрывов, задержка как в обычном созвоне
- [ ] 5.2 Говорящего видно по рамке плитки
- [ ] 5.3 Кнопка микрофона и клавиша M (и Ь в русской раскладке): у других на плитке — «микрофон выкл.»
- [ ] 5.4 Кнопка звука и клавиша D (В): перестаёшь слышать других и микрофон выключается; включение возвращает как было
- [ ] 5.5 «⋯» в правом верхнем углу чужой плитки — громкость 0–200 % только у себя; после перезапуска для этого имени она сохранилась
- [ ] 5.6 «Настройки звука» на своей плитке: смена микрофона и динамиков на лету, «Проверить звук» играет в выбранные динамики
- [ ] 5.7 Если говорят больше трёх человек сразу, слышно троих, и голоса не «перещёлкиваются» каждую секунду
- [ ] 5.7a Push-to-talk: «Настройки звука» → «Говорить, только пока нажата клавиша», выбрать клавишу. Без клавиши не слышно; с зажатой — слышно, кнопка микрофона показывает «Говорите»; у других не мигает «микрофон выкл.»
- [ ] 5.7b Push-to-talk поверх игры или другого окна (Windows, macOS после «Универсального доступа», Linux X11) — работает; на Wayland — только в окне Tolki, и это написано в настройках
- [ ] 5.7c «Клавиши в любом окне»: задать сочетание для микрофона и звука; в звонке оно срабатывает, когда активно другое приложение; после выхода из звонка сочетание снова работает в других приложениях; занятое другим приложением — «Это сочетание занято другим приложением»
- [ ] 5.8 В шапке — «N мс · через организатора (UDP)»; N похоже на правду (в пределах страны — десятки мс)
- [ ] 5.9 Звонок 30+ минут: качество не портится, приложение не тормозит

## 6. Демонстрация экрана

- [ ] 6.1 «Экран» открывает «Что показать» с превью экранов и окон на отдельных вкладках; «Обновить список» подхватывает новое окно
- [ ] 6.2 macOS: без разрешения «Запись экрана» — объяснение и «Открыть настройки»; после разрешения и перезапуска показ работает
- [ ] 6.3 Linux Wayland: экран выбирается в системном окне; X11 — в окне приложения
- [ ] 6.3a «Звук компьютера» (Windows; macOS 14.2+): галочка в «Что показать», по умолчанию выключена. С ней участники слышат видео или музыку с компьютера показывающего, в стерео; голосов звонка в этом звуке нет (никто не слышит себя с задержкой); после «Остановить» звук пропадает. macOS: при первом показе со звуком — запрос разрешения. На Linux галочки нет
- [ ] 6.4 Участники видят экран крупно, подпись «Экран: имя», в углу «1080p · N к/с · N Мбит/с»; «На весь экран» работает
- [ ] 6.5 Режим «Плавно»: видео или игра идут плавно; «Чёткий текст»: мелкий код читается
- [ ] 6.6 Показывающему — нагрузка на процессор: в «Мониторинге системы» / «Диспетчере задач» Tolki (все процессы) во время показа видео — не больше ~15 % одного ядра на компьютере с аппаратным кодеком
- [ ] 6.7 Маленькое окно у зрителя (или «Все участники») — экран мельче, но не дёргается; свёрнутое окно — при разворачивании показ продолжается сразу
- [ ] 6.8 «Показать свой» у второго участника: показывающему приходит запрос; «Уступить» — показ переходит, «Продолжить показ» — второй видит отказ
- [ ] 6.9 «Остановить» (или остановка из системы) — у всех показ пропадает, плитки возвращаются

## 7. Связь рвётся и возвращается

- [ ] 7.1 У участника выключить Wi-Fi на 5–10 с: «Переподключение…», после включения звонок продолжается сам, голос и экран возвращаются
- [ ] 7.2 Wi-Fi выключен дольше 30 с: «Связь с комнатой потеряна», «Попробовать снова» после включения возвращает в комнату
- [ ] 7.3 Ноутбук участника — в сон на минуту и обратно: понятное состояние, войти снова можно
- [ ] 7.4 У организатора пропала сеть на 5–10 с: участники переподключаются сами
- [ ] 7.5 Приложение организатора закрыто принудительно (снять задачу): у участников «Переподключение…», через 30 с — «Связь с комнатой потеряна»

## 8. Ошибки, которые должны быть понятными

- [ ] 8.1 Ссылка с изменённой буквой в `fp=` — «Сертификат изменился», подключаться не предлагает
- [ ] 8.2 Шесть неверных паролей подряд — «Слишком много неверных попыток…», через минуту снова можно
- [ ] 8.3 Ссылка на закрытую комнату — «Организатор не в сети»
- [ ] 8.4 Нет интернета на главном экране — строка внизу и экраны не зависают, «Проверить снова» работает после появления сети

## 9. Без звонка

- [ ] 9.1 Приложение открыто без звонка 5 минут: в «Мониторинге системы» / «Диспетчере задач» почти 0 % процессора
- [ ] 9.2 Свёрнутое приложение — тоже почти 0 %

## 10. Логи

- [ ] 10.1 После звонка «Помощь → Сохранить логи…» (Windows/Linux — через Alt): в «Загрузках» появился `tolki-logs-<дата>.txt`, открылась папка с ним
- [ ] 10.2 В файле есть события звонка (вход, «участник 3f2a joined», связь UDP/TCP); нет имён, названия комнаты, пароля, ссылки и полных IP-адресов

Проверяется, только когда опубликована версия новее установленной.

- [ ] 11.1 На главном экране — «Доступна версия X», «Скачать» открывает страницу релиза, «Скрыть» убирает плашку до следующего запуска
- [ ] 11.2 Установка новой версии поверх: «Недавние комнаты», имя и настройки звука сохранились
